# Telepathy

A desktop code structure visualization tool inspired by [Sourcetrail](https://github.com/CoatiSoftware/Sourcetrail). Reads C++ symbol data from Visual Studio's IntelliSense database (`Browse.VC.db`) and renders interactive class hierarchies, member lists, and source code previews.

## Screenshot

*(Launch the app and open a Browse.VC.db to see the 3-panel UI)*

## Features

- **Class browser** — filterable list of classes/structs from the VS IntelliSense DB, with forward declarations resolved to the real definition (most members wins)
- **Inheritance graph** — interactive node graph showing base and derived classes using React Flow; selecting/pinning a member whose type is a known class adds that type as a node with a dashed purple edge
- **Member inspector** — right panel with search/filter, sort (line/name/kind), group toggle cycling through none/kind/base-origin, and Ctrl+Click pin-to-graph
- **Inherited members** — base class members are collected recursively and shown alongside own members, tagged with the originating base class name
- **Source preview** — reads source files directly from disk, shows filename + line number in header, highlights the selected member's line
- **Back/forward navigation** — ← / → buttons (+ Alt+Left / Alt+Right shortcuts) maintain a class visit history stack
- **Ctrl+K search** — global fuzzy search across all symbols
- **Plugin architecture** — data source abstraction; first plugin reads `Browse.VC.db` via SQLite

## Quick Start

### Prerequisites

- Node.js 20+
- A Visual Studio solution that has been opened at least once (to generate `Browse.VC.db`)

### Install & Build

```bash
npm install
npm run rebuild-native   # rebuild better-sqlite3 for Electron
npm run build            # electron-vite build
```

### Run

```bash
# Option 1: dev mode (hot reload)
npm run dev

# Option 2: run production build
node_modules/electron/dist/electron.exe out/main/main.js
```

Once launched, the app auto-loads the configured database or you can open one via the UI.

### Test

E2E tests use Playwright connecting to Electron via Chrome DevTools Protocol:

```bash
# Start Electron with CDP enabled
node_modules/electron/dist/electron.exe --remote-debugging-port=9222 out/main/main.js

# In another terminal
node test-electron.mjs
```

## Data Source

The first (and currently only) plugin reads **Visual Studio's `Browse.VC.db`** — an SQLite database generated by IntelliSense. Typical path:

```
<solution>/.vs/<project>/v18/Browse.VC.db
```

### What works
- Class/struct listing with deduplication (`GROUP BY name, kind`)
- Forward declaration disambiguation (prefers definition with the most members)
- Member queries (functions, fields, enums, typedefs) including inherited members from base classes
- Type resolution — member return/field types are resolved to class IDs when possible
- Inheritance relationships via `base_class_parents` table
- Source code reading from disk

### What doesn't work (DB limitation)
- **Call graphs** — the `symbols`, `symbol_refs`, and `symbol_relations` tables are empty in tested databases. Call chain visualization requires a different data source (e.g. a VSIX extension or clangd).

## Project Structure

See [ARCHITECTURE.md](./ARCHITECTURE.md) for detailed design documentation.

```
telepathy/
├── electron/          # Electron main + preload processes
│   ├── main.ts        # BrowserWindow setup, plugin registration
│   ├── preload.ts     # contextBridge API (window.telepathy)
│   └── ipc/           # IPC channel handlers
├── plugins/           # Data source plugins (main process)
│   ├── core/          # Plugin interface + PluginManager
│   └── vs-browse-db/  # Browse.VC.db SQLite plugin
├── src/               # React renderer
│   ├── components/    # UI components (5 panels)
│   ├── stores/        # Zustand state
│   ├── api/           # Renderer-side IPC wrappers
│   └── types/         # Shared type definitions
└── test-electron.mjs  # E2E test script
```
