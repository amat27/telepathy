# External Integrations

**Analysis Date:** 2026-03-17

## APIs & External Services

**None.** Telepathy is a fully offline desktop application. It makes no HTTP/network requests to external services. All data comes from local SQLite databases and local filesystem reads.

## Data Storage

**Databases:**
- Visual Studio Browse.VC.db (SQLite3)
  - Type: SQLite database generated by Visual Studio IntelliSense
  - Client: `better-sqlite3` (native Node.js binding)
  - Access mode: Read-only (`readonly: true`)
  - Connection strategy: URI mode with `immutable=1` (fallback to plain readonly if URI fails)
  - Pragma tuning: `journal_mode = OFF`, `cache_size = -64000` (64MB)
  - Implementation: `plugins/vs-browse-db/VsBrowseDbPlugin.ts`
  - Typical path: `<solution>/.vs/<project>/v18/Browse.VC.db`
  - Schema tables used:
    - `code_items` — symbols (classes, structs, functions, members, etc.) with kind, name, type, location
    - `base_class_parents` — inheritance relationships
    - `files` — file path index
  - Schema tables present but empty: `symbols`, `symbol_refs`, `symbol_relations` (no call graph data available)
  - All queries use prepared statements (12 statements cached in `VsBrowseDbPlugin`)
  - File cache: all `files` rows loaded into `Map<number, string>` on init

**File Storage:**
- Local filesystem only
  - Source code files read via `fs.readFileSync()` for code preview
  - Path normalization via `path.normalize()` in `plugins/vs-browse-db/VsBrowseDbPlugin.ts`
  - No file writing or modification

**Caching:**
- In-memory only
  - File ID → path map cached in `VsBrowseDbPlugin.fileCache` (`Map<number, string>`)
  - SQLite prepared statements cached as class fields
  - 64MB SQLite page cache via pragma

## IPC Communication (Internal)

The main/renderer process boundary uses Electron IPC as the sole integration layer:

**Channel definitions:** `src/types/model.ts` (`IPC_CHANNELS` constant)

| Channel | Direction | Handler | Purpose |
|---------|-----------|---------|---------|
| `plugin:list` | renderer → main | `pm.listPlugins()` | List registered plugins |
| `plugin:init` | renderer → main | `pm.activate(name, {dataPath})` | Initialize/activate a plugin |
| `query:classes` | renderer → main | `pm.getClasses(filter?)` | Get class/struct list |
| `query:class-members` | renderer → main | `pm.getClassDetail(id)` | Get class with members |
| `query:class-hierarchy` | renderer → main | `pm.getClassHierarchy(id)` | Get inheritance graph |
| `query:search` | renderer → main | `pm.searchSymbols(query, kinds?, limit?)` | Symbol search |
| `query:source-snippet` | renderer → main | `pm.getSourceSnippet(file, line, ctx?)` | Read source code |
| `dialog:open-db` | renderer → main | `dialog.showOpenDialog()` | File picker for .db |
| `query:call-graph` | defined but not implemented | — | Reserved for future use |
| `dialog:open-folder` | defined but not implemented | — | Reserved for future use |

**Bridge:** `electron/preload.ts` exposes `window.telepathy` via `contextBridge.exposeInMainWorld()`
**Renderer wrapper:** `src/api/index.ts` provides typed async functions that call `window.telepathy.*`

## Plugin System (Internal Integration Point)

**Interface:** `plugins/core/types.ts` defines `CodeAnalysisPlugin`
**Manager:** `plugins/core/PluginManager.ts` — registry + routing proxy
**Current plugins:**

| Plugin | File | Data Source |
|--------|------|-------------|
| `vs-browse-db` | `plugins/vs-browse-db/VsBrowseDbPlugin.ts` | Visual Studio Browse.VC.db |

**Plugin lifecycle:**
1. Registered in `electron/main.ts`: `pluginManager.register(new VsBrowseDbPlugin())`
2. Activated via IPC: `pluginManager.activate('vs-browse-db', { dataPath: '/path/to/Browse.VC.db' })`
3. Disposed on window close: `pluginManager.disposeAll()`

**Adding a new plugin:**
1. Implement `CodeAnalysisPlugin` interface from `plugins/core/types.ts`
2. Create directory under `plugins/` with implementation
3. Import and register in `electron/main.ts`
4. No changes needed to IPC layer or renderer — PluginManager proxies all queries
